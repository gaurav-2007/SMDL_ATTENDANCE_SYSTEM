Answer

The SMDL Smart Attendance System automates college-wide attendance tracking through an integrated pipeline of automated timetable synchronization, campus geofencing, selfie verification, faculty review, and real-time push notifications.

  1. Automated daily timetable synchronization converts weekly academic schedules into active, trackable lecture slots in Indian Standard Time.
  2. Multi-factor attendance verification pairs browser HTML5 Geolocation within a 100-meter campus perimeter with live camera selfie capture.
  3. Faculty retain full control to initiate lectures, review student verification photos in real time, and execute audited attendance overrides.
  4. Multi-tier architecture powered by Express 5, Supabase PostgreSQL, Supabase Storage, and Firebase Cloud Messaging ensures secure, low-latency execution.

The system coordinates three distinct phases across the college day: schedule preparation, student attendance submission, and faculty review.

  1. 1. Daily Schedule Sync ↗

    The scheduler converts the division's weekly timetable matrix into active date-specific lecture slots each morning in IST.

  2. 2. Campus Geofence Validation ↗

    When the lecture status is ONGOING, students within 100 meters of college coordinates can open the attendance screen.

  3. 3. Live Selfie Verification ↗

    The student captures an uncompressed camera photo; the backend validates JPEG magic bytes and persists it to Supabase Storage.

  4. 4. Faculty Monitoring & Override ↗

    Teachers inspect incoming attendance selfies in real time and can override individual student statuses with audit logging.

  5. 5. Lifecycle Closure & Reports ↗

    Ended lectures transition to COMPLETED; aggregate attendance percentages and defaulter alerts update automatically.

Core Verification & Protection Mechanisms

Multiple defensive layers prevent proxy attendance, credential theft, and out-of-boundary access.

  • Campus Geofencing: Haversine formula calculates distance from college coordinates; requests beyond 100 meters are rejected immediately.
  • Photo Liveness & Magic-Byte Validation: Server inspects binary buffer magic bytes to ensure real image data before persisting to cloud object storage.
  • Strict Time-Window Clamping: Attendance is accepted only while the lecture is ONGOING and between start time and end time plus 60 minutes.
  • Audit-Logged Manual Overrides: Every faculty attendance override stores teacher ID, timestamp, and previous status in the audit log table.
  • JWT & Role-Based Middleware: Every route verifies Bearer tokens and confirms active account status before dispatching requests.
