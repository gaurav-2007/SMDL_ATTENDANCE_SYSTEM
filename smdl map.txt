SMDL College Smart Attendance & Communication System
1. Project Overview

I want to develop a professional attendance and communication system for SMDL College, Kalamboli, Maharashtra.

The system should be designed as a real-world college application, not just a demo project.

The main objective is to

Make attendance easier to record.
Reduce fakeproxy attendance.
Verify that a student is physically present at the college.
Allow teachers to review and correct attendance.
Handle students who do not have a personal smartphone.
Provide a direct communication channel between teachers and students.
Allow teachers to send announcements, PDFs, images and other important information.
Make the system scalable and secure enough for actual college deployment.
Ensure that only college-approved teachers can access teacher functionality.

The final goal is to present the system to the college and, if approved, deploy it for real use.

2. User Roles

The system will initially have three main roles

A. Student

Each student will have an individual account.

Students should be able to

Login using their college credentials.
Mark attendance.
Complete attendance verification.
View their attendance percentage.
View subject-wise attendance.
View attendance history.
Receive teacher announcements.
Viewdownload shared PDFs and images.
Receive important class information.
B. Teacher

Teachers will have a separate account.

However, a teacher account must NOT become active immediately after registration.

A teacher who wants to use the system must first submit a registrationapplication.

The account will remain in a

PENDING APPROVAL

state until an authorized administrator approves it.

Only after admin approval should the teacher receive access to the teacher dashboard and teacher functionality.

C. Admin

The administrator will be responsible for approving and managing teacher accounts.

Admin should be able to

View pending teacher registrations.
Review teacher information.
Approve teacher accounts.
Reject teacher accounts.
Disable an already-approved teacher account if required.
Manage teacher permissions.
Assign teachers to subjectsclasses.
Manage students and academic structure.

10. Student Attendance Process

Attendance should use multiple verification conditions.

Step 1 — Student Login

The student logs into the application using their registered account.

Step 2 — Location Verification

The system checks whether the student is physically inside the allowed college locationgeofence.

Student attempts attendance
        ↓
Check current location
        ↓
Inside allowed college area
        
     YES  NO
      ↓    ↓
 Next     Attendance rejected

The exact geofence radius should be configurable by the administrator.

Step 3 — Selfie Verification

After successful location verification, the student must capture a selfie showing that they are physically present.

Preferably, the student should capture the selfie directly through the application rather than simply selecting an old image from the gallery.

The attendance attempt should store appropriate verification information such as

Student ID
Lecturesubject
Date
Time
Location verification result
Selfie submission status
Attendance status
Step 4 — Attendance Confirmation

Attendance should be marked only when the required conditions are successfully satisfied.

Student authenticated
        +
Location verified
        +
Attendance selfie captured
        ↓
Attendance recorded

If a required condition fails, attendance should not automatically be marked.

11. Important Anti-Cheating Requirement

The system is intended to reduce proxyfake attendance.

However, the system should NOT assume that location + selfie makes cheating impossible.

The architecture should therefore allow future improvements such as

Liveness verification
Face matching
Duplicateselfie analysis
Devicesession verification
Time restrictions
Suspicious attendance flagging
Teacher review

These advanced features should be evaluated separately before implementation because they involve privacy, consent, accuracy and technical considerations.
